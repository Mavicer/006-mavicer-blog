个人网站上线了，感觉空荡荡的，那就多写几篇流水账把它充实一下吧。

也好，借这次机会，总结一下这一个月以来，从接触 Python 到开发出独立个人博客等一系列网站的踩坑经历与心得。

什么？你问我为啥高考毕业以后才开始"接触python"，哈哈，高中的微机课，书可以不带，装满游戏的U盘必须带，直到合格考的前几天，才厚着脸皮在周末申请到学校找信息技术老师补习，最终也是合格了，好结局(^_^)v

然而，百无聊赖的暑假生活却意外激起了我的学习欲望。闲不下来的我开始在抖音与 B 站上搜索"准大一新生应该提前学习的知识"，Python 赫然位列榜首。于是我花了一上午，在 ChatGPT 的帮助下在 Mac 上配置好了开发环境。七天，从 `print` 到循环，再到数据集、函数模块与嵌套解包，我逐渐对编程产生了浓厚兴趣——尤其是当自己写的程序真的能按预想正确运行时，那种具体可感的成就感便将兴致勃勃的我推向了下一阶段。

学习 Python 的过程中最开心的事，就是能用现有知识真正做出一个能解决现实问题的程序。于是我的文件夹里开始出现了体检报告分析程序、高考模拟查分系统、高考模拟志愿填报系统等项目。随着学习深入，我不断加入 8×8 口令卡验证、信息储存与调用等新功能，开发出 2.0、3.0 版本。渐渐地我不满足于让项目只在 Terminal 中运行，顺其自然地接触到了网站开发。

也就是这时候，我接触到了 Agent 这一概念。本着"靠 AI 学习 AI"的想法，我花了一下午向 ChatGPT 请教何为 Agent、如何配置开发环境。起初用 Cursor，结果第一个项目做到一半额度用完了，可恶。最终选择了 VS Code 作为长期稳定的开发平台。

我选了最便宜的方案：CC Switch + DeepSeek V4 Pro 的穷鬼组合。刷多了抖音上 Codex 制作大师级 PPT 的视频，不会写 prompt 的我天真地启动了 AI PPT Agent 计划，幻想做出像 WPS 或 Gamma 那样的 PPT 生成器。烧掉 4 个亿 tokens 后，得到了一坨 600MB 的屎山代码——不会分析主旨，没有审美能力，唯一可用的配图搜索引擎还时不时抽风，生成诡异的灰色占位图。

现在的我当然知道，这是因为 DeepSeek 在图像处理方面的天生弱势，那些所谓小白零基础做出大师级 PPT，也不过是复制粘贴了 motionsites.ai 里具体到像素点分布的 prompt。但这暴露出更深层的问题：是否只要把问题用人话丢给 AI，它就能帮你完美完成一个项目？当然不能。AI 不是神，也没有读心术。作为项目架构师与决策者，若只是慵懒地坐在一旁，时不时瞥一眼屏幕，不停点按 "yes, and use auto mode"——这将是多么滑稽而发人深思的画面。

经历了第一次全面失败后，我开启了 AI 旅游网站的开发。为什么是旅游网站？原因很简单：刚好在 motionsites 找到了一个免费的 hero prompt，而且这个项目能复用上一个失败项目的图片搜索引擎。但光有这些不够，我开始摸索让 Agent 按轨道推进的方法。开发新功能前，先打开 Plan Mode 而不是直接 coding，一边自己浏览 plan，一边把 plan 扔给 ChatGPT 让它分析可行性。效果显而易见——bug 越修越多的问题显著改善了。最搞笑的是我让它找"重庆"的风光图片，它返回一张沙漠的图片。核验代码后发现 DeepSeek 居然是用分析图片像素颜色分布来判断是否符合要求的，于是我把结果反馈给 GPT，讨论出新检索方案并指导 DeepSeek 修改，这才让功能真正可用。

当然这只是一次小规模测试。我的目标是开发出有实用价值的网站，于是深思熟虑后开始了大学学习通网站的开发。原因很现实：在信息过载而混乱的当下，是否可以设计一个面向大学生的一站式成长平台，让学生不再被碎片化信息困扰，而是在一个系统中完成大学规划、资源查询和个人管理？说干就干。

这一次，综合前面的经验，我决定尝试多 Agent 开发模式。看起来像是把问题复杂化了？实际上，如果把我与 Agent 比作一个软件开发公司，原先的单 Agent 模式就像只招了一个员工，同时负责需求理解、架构设计、编码、调试、优化，必然导致上下文无限拉长，缺失架构监督与严格审查更会导致方向偏移和"局部最优"的死循环。如果我能够同时雇佣多名员工，分别负责理解需求撰写 prompt、架构设计与编码、数据收集与采样、验收总结与审查，就能优雅地保证项目按计划推进。

然而新问题又出现了。原本设计的"个性推荐"板块已经不是简单的标签系统，而是小型推荐引擎。我尝试协同过滤，但需要大量用户-资源交互数据，项目初期根本无法训练可靠的推荐模型。又尝试引入轻量化本地模型，但 LLM 更适合语义理解和解释，而非直接承担资源筛选，幻觉严重。最终阶段性放弃了复杂的推荐系统——不过我还会回来的。

看完 Vito Wang 学长的个人博客后，我一直渴望拥有一个属于自己的博客，可惜找不到同款模板。于是灵机一动，尝试从前端逆向复刻，采用多 Agent 并行的方式，1:1 还原了模板网站。这个经历让我意识到：如果我能逆向别人的系统，别人同样能分析我的代码。因此我开始关注前端代码暴露问题，将敏感数据如 API Key 保存在后端而非前端，并进一步考虑输入验证、权限检查和数据隔离。

经过这几天 vibe coding 的初步学习，我逐渐总结出几条降低 tokens 消耗的技巧。如果每次让 Agent 读取整个项目，token 消耗巨大、响应速度下降、重点信息容易被淹没。因此我开始建立项目上下文文档——README.md、ARCHITECTURE.md、DEVELOPMENT.md、TODO.md——这样 Agent 不需要重新分析整个项目，可以快速恢复上下文。多 Agent 协作也是同理，保证各 Agent 对项目的认知在同一水平线是实现统一目标的前提，因此也不妨建立 COMMUNICATION.md 让 Agent 之间相互传递信息。在 AI 时代，优秀的软件工程不仅需要管理代码，也需要管理 AI 的认知成本。

接下来我还会继续学习并尝试在网站中接入 API 以打造真正的智慧推荐系统，也会继续探索如何让 Agent 在上下文丢失后仍保持项目理解。回顾整个过程，最大的收获并不是学习了多少框架，而是逐渐形成了工程师思维：软件开发不是简单地让程序运行，而是在有限资源和复杂环境下，设计可靠、可维护、可扩展的系统。大学四年，我希望继续保持这种探索欲，在 AI 快速发展的时代，成为那个不仅会使用工具，也能够创造工具的人。
